# Corrections log: findings checked against the original workflow

This repository is a modular re-implementation of the original CYP3A4 TDI workflow by Jackson Burns (referred to as **JB** below;
identifiers `JB-01` ... `JB-15` label individual findings). Each finding was checked against the original source: `JB_CYP3A4/`
(scripts 01-12, `config.py`, `common.py`, `features.py`, `embeddings.py`). Scripts 13-21 of the original (post-hoc analysis and candidate
generation) are not part of the pipeline, were not reviewed line by line and are not included. `JB_CYP2D6/` in the original archive is a
mislabeled CYP3A4 copy and is not used.

"Verified here" means checked on saved artifacts of the original run with numpy/pandas/pickletools. No pipeline step was executed during
this review (RDKit, LightGBM, torch, chemprop and TabICL were unavailable), so no runtime claim is made.

## Additional observations (new, evidence-based)
* The shipped `submission_CYP3A4_is_TDI.csv` has columns `SMILES, Molecule_Name, CYP3A4_is_TDI`, while script 12 writes
  `Molecule_Name, SMILES, CYP3A4_is_TDI`. The pipeline uses the script's order (configurable in `config/isoforms/CYP3A4.yaml`).
* `fallback_debug` mode (base-only outputs) and the `--ext` AID1851 path were **removed**: neither was part of the shipped run,
  and a partial-member run must never look like a result. `extbase`/`tabcpext` remain only in `member_order` (tie-break order).
* `jb_cache_verified_descriptor_names.json` is used as a *reference check*, not a substitute for RDKit.

## What numbers can change versus the baseline
PCA fold scope (JB-03) changes `oof_tab`/`oof_tabcp`, hence ensemble weights, nested OOF, the selected fraction and the
shipped positives. The count convention (JB-04) changes every best-fraction MCC and the positive count by 1. Deterministic
LightGBM can change `oof_base`/`oof_emb`/final models slightly. No claim is made about MCC or leaderboard rank.
Use `--profile baseline` for the original behaviour (see README).
